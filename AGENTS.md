- Full hair-system fulfillment uses _shared/hairSystemFulfillment.ts; admin supplier-only recovery independently verifies one paid live session and uses the same supplier dispatch/atomic claim helper without buyer, CRM, order, or webhook writes — prevents late customer messages. Both use the existing Vlix relay; OAuth stays in Vlix.
- Supplier channel claims run independently of failed CRM sync; buyer channels retain the CRM gate, and every shared fulfillment entry checks the hold fail-closed — contact outages cannot suppress production sheets or bypass safety pauses.
- Hair-system webhook verifies against the encrypted DB signing secret (app_settings.hair_system_webhook_secret_ref) before the env fallback, logs every delivery to hair_system_webhook_attempts, and returns 503 without sending while app_settings.hair_system_fulfillment_hold is true — rotation and replay pause happen via API, no dashboard needed.
- Automatic hair-system paths (webhook, buyer return) fulfill only checkouts created after app_settings.hair_system_fulfillment_cutover and never its excluded_order_ids; manual reconcile requires exactly one order ID — stops Stripe retries from replaying historical orders.
- Hair-system checkout stores prepayment data only in the server-only hair_system_checkout_drafts table; real orders are created by hair_system_materialize_paid_draft only after Stripe confirms paid, unique per (session, system index) via payment_reference — abandoned checkouts never become receipts. Legacy order_ids branch kept for rollback.
- receive-order inserts only when a Stripe payment reference in the payload is independently confirmed succeeded; form-only webhooks fail closed (202, no row). Receipts/manufacturer lists exclude status pending_payment.
- Resource Save controls use the shared FileDownloadButton and fileDownloads helpers, prefetching visible files and delivering local blobs instead of navigating to remote URLs; prepared ZIPs require a fresh save click to retain mobile user activation.
- Directory enrollment and search share geocodeZip error handling; the server validates coordinates from a ZIP-specific lookup so provider outages are not mislabeled as invalid member addresses.
- Training entry always opens lessons independently of directory enrollment; certification/listing actions remain separate so unfinished listings cannot block review.
- Auth status reads use identity/version coordination, reject failed initial lookups, and refresh resolved same-user sessions without unmounting lessons; stale responses cannot restore old-user access.
- Course and lesson fetch failures show a retryable loading error, never an empty-catalog or missing-module claim; listing prompts require a successful absent-listing result.
- Native hair-system receipt retrieval uses a read-only owner/admin endpoint with paid Stripe seller/session/owner/draft verification; checkout-level receipts consolidate system rows so payment totals and shipping are never duplicated. Future snapshots are stored only inside the existing paid path without changing notification inputs.
- Hair-system Stripe TEST mode lives only in hair-system-test-checkout/-webhook, _shared/hairSystemTestMode.ts and hair_system_test_* tables; it captures messages to a sink and never calls relay/GHL — keeps test orders out of production paths and is removable as a unit.
- Live notification verification is a separate action on the existing checkout using a deterministic existing-draft primary-key reservation; it shares signed paid fulfillment and conditional message builders, never a parallel processor — ensures one session and preserves ordinary prices/flows without schema changes.
- Certificate printing uses a predecoded image in the main document and a fixed landscape print page with contain sizing — avoids Safari popup failures, cropping, and screen-size-dependent alignment.
- GHL kit fulfillment is isolated in hair-system-kit with a server-only activation gate and permanent per-location/order delivery reservations; its fresh-payment reader remains unbound until the real relay read contract is verified, preventing invented evidence or accidental sends. Supplier kit rows use raw external_order_id and null user_id, with kit-only restrictive read access and the existing /newtimes manifest/shipping contract.
- /newtimes is intentionally public (owner decision) and reads/writes only through the newtimes-orders function (displayed fields; mark placed/undo/tracking/reopen with optimistic checks; no delete) — keeps anonymous orders-table RLS closed; /admin/orders keeps direct admin access.
- Supplier package edits and explicit completion use shared reducers in public functions and authenticated hooks; tracking saves remain working, completion alone sets shipped/archive timing, undo preserves tracking and suppresses repeat shipment alerts, and reopen archives/clears tracking and completion — prevents divergent state and stale labels.
- Buyer shipping notices are queued only by an orders trigger on newly added tracking keys (10-minute due, coalesced per order) and sent by buyer-shipping-notify, which re-reads the order and records one outcome per channel; ambiguous sends are terminal — prevents stale, duplicate, or backfilled customer messages.
