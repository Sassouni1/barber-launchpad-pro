- Member access comes only from public.member_access_grants (verified live paid Stripe checkouts/charges, paid hair-system orders, GoHighLevel paid transactions, an admin grant with a reason, or the exact HighLevel member-access tag via _shared/memberTagAccess.ts); every change is logged append-only in member_access_events and the access switch (app_settings.member_access_enforcement) can only be turned on by naming the exact number of accounts it will block — prevents lockouts and silent approvals.
- Accounts created on/after public.member_access_new_account_cutover() (fixed in SQL, from auth.users.created_at) need a grant; every older account (any role, independent of the access switch) keeps existing-account access that ends only on an explicit post-cutover admin revocation (revoked_by set, revoked_by_system false; admin "End access" records a revoked admin_grant) — owner decision that existing accounts never lose access silently.
- HighLevel tag access (_shared/memberTagAccess.ts, used by member-signup and member-access-claim) reads the approved location through hairSystemGhlAccess, matches only the exact normalized email, and writes only its own ghl_member_tag grant (one per email): a successful read without the tag revokes only that grant, a failed read changes nothing, and an admin-ended tag grant is never auto-reinstated — the tag is not a purchase and never touches roles or the access switch.
