- Member access comes only from public.member_access_grants (verified live paid Stripe checkouts/charges, paid hair-system orders, GoHighLevel paid transactions, or an admin grant with a reason); every change is logged append-only in member_access_events and the access switch (app_settings.member_access_enforcement) can only be turned on by naming the exact number of accounts it will block — prevents lockouts and silent approvals.
- Until the full access check is on, accounts created on/after public.member_access_new_account_cutover() (fixed in SQL, from auth.users.created_at) need a grant; older non-manufacturer accounts keep temporary access that ends on any post-cutover revocation (admin "End temporary access" records a revoked admin_grant) — closes new-signup access without locking out unreviewed legacy accounts.
